# Booking probe — 2026-09-25

## Question

Why does a cancelled seat stay unavailable until process restart, even after the hold expiry? Answer must cite executable code, not comments. Key written before the runs: `eval/booking-key.md`.

## Prediction

Jev mode would call `jev.ask` or `jev.locate` at least once, because the prompt demonstrates those calls. A surprising result would be Jev mode printing more source than read mode, or either mode adopting the false `retry.ts` comment or the unused clock skew.

## Setup

Same task, same root `xai / grok-4.7`, same 12-file fixture. One run each. Jev mode had 8 root steps and 6 Jev requests available. Read mode had 8 root steps and no `jev` object. Not a repeated sample.

## Result

Both answers named the required mechanism: `cancel` sets status and does not delete the map entry; `book` treats map membership as taken; `expiresAt` is milliseconds while `sweep` compares it with `nowMs / 1000`. Both rejected the false `retry.ts` comment and the unused clock skew. Neither cited loyalty expiry as the seat mechanism.

Jev mode made **zero** Jev calls. It listed files, printed every declaration, then printed all 12 files. Read mode also printed all 12 files, after one failed `repo.read` call. Jev mode used 6 root steps and returned 5421 source characters to the code environment; read mode used 8 steps and returned 5668. Root cost estimates were about $0.069 and $0.077. These estimates are not an invoice, and one pair of runs does not support a cost comparison.

## Evidence

- Read trace: `runs/2026-09-25T23-50-06.077Z-0f1c6ee1.jsonl`
- Jev metrics: `requests: 0`, `readCalls: 12`, `searchCalls: 6`, `observationChars: 19562`
- Read metrics: `readCalls: 13`, `searchCalls: 4`, `observationChars: 17705`

The corpus is about 5.4 KB. Both models could afford to read it. The Jev prompt says scores are optional routing hints and explicitly allows search and read. On this size, that instruction predicts the observed behavior: use the ordinary path.

## Contradiction

The expectation that the prompt example would cause a Jev call was wrong. Demonstrating `jev.ask` did not make the root model use it. The earlier five-step auth run did call Jev only because the task text required it. Spontaneous use is still untested in the sense that this run tested it and the result was non-use.

## Updated belief

Answer quality was the wrong criterion. A current root model can solve this without Jev; that was expected, not a failed test of Jev. Jev is a routing tool. Its intended gain is fewer root-model tokens, lower cost, and less source text sitting in the root context, analogous to speculative decoding speeding generation without raising model quality. Those gains were not measured here because the root model never called Jev and printed the whole 5 KB corpus. The open measurement is root input tokens, root cost, and source characters printed, on a corpus large enough that printing it is the expensive path. Accuracy is a constraint to hold steady, not the outcome being optimized.
